## W1 (BLOCK) -- failover re-exchange is an unrated outbound amplifier

`core/src/transport/swarm.rs:4944-4970` (native), same shape at `:7138-7154`
(WASM). Introduced by `e5a6bc4b`.

The new `SwarmEvent::ConnectionClosed { num_established > 0 }` arm sends a fresh
`LedgerExchangeRequest` on every partial close. Nothing rate-limits it:
`ledger_exchange_guardrails` is consumed only in the inbound request arm
(`:3969`, `:3975`), and `ledger_exchanged_peers.insert(peer_id)` throttles
nothing because the next close removes the entry again.

Per close, the native path:

- calls `exchange_response_entries(...)`, which takes `entries.lock()` and
  filters the entire ledger up to `LEDGER_EXCHANGE_MAX_RESPONSE_PEERS`;
- builds and emits an outbound request.

Both run on the `select!` thread that also owns message delivery -- the exact
starvation surface the NEW-5 comment above the inbound bucket cites as the
reason the inbound limiter exists.

**Reachability.** An authenticated peer holding one connection opens a second
connection and closes it, repeatedly. Attacker cost is one TCP+Noise handshake
per cycle; our cost is a full ledger scan plus a request emission per cycle.
`connection_limits` caps concurrency, not churn rate. It is also reachable with
no attacker present: a flapping BLE/LAN/relay multi-path peer -- the exact
condition this fix targets -- produces the same churn.

The WASM arm sends `peers: Vec::new()`, so it skips the ledger scan, but still
emits one unrated request per churn event.

**Fix shape** (proposed only; the reviewer-independence rule means whoever
implements this cannot be its signatory):

- gate the re-exchange with the existing per-peer bucket
  (`ledger_exchange_guardrails.consume_peer_token`), or
- enforce a per-peer minimum interval between failover re-exchanges, and
- consider re-exchanging only when the closed connection is the one that carried
  the prior exchange, rather than on any partial close.

## Verified clean

Each claim checked against the code, not accepted from the PR thread.

1. **Requester-bound private disclosure.** `is_disclosable_on_rfc1918_network`
   takes `requester_addr: Option<&str>` and fails closed on `None`, on an
   unparseable address, on a circuit requester, and on a circuit entry. The
   requester address comes from `ConnectionTracker`, i.e. the observed transport
   peer, never from the requester's payload.
2. **CGNAT excluded symmetrically.** `is_private_adjacency_ip` requires
   `ip.is_private()` for v4 and rejects NAT64-embedded CGNAT for v6, applied to
   both requester and entry before `same_private_subnet`. The subnet test is /24
   (v4) and /64 (v6 ULA), narrower than the old `rfc1918_class` behaviour.
3. **Concrete-listener requirement.** Empty or non-IP listener lists produce an
   empty `concrete_local_ips` and fail closed. Regression test present.
4. **Connection-bound disclosure.** `ConnectionTracker` is keyed
   `PeerId -> {connection_id -> endpoint}`; the ledger-exchange and
   address-reflection request arms use `get_connection_by_id`. A stale
   direct-LAN path can no longer authorize disclosure on a relayed connection.
5. **Per-connection teardown, no leak.** The partial-close arm calls
   `remove_connection_by_id`; the terminal arm still calls `remove_connection`
   for the whole peer. Verified native (`:4930`, `:4977`) and WASM (`:7127`,
   `:7161`).
6. **Block enforcement across protocols.** `peer_is_blocked` gates
   ledger exchange (request and response), address reflection, registration,
   relay/custody admission, custody dispatch, and the outbound
   `RegisterIdentity`/`DeregisterIdentity`/`RequestAddressReflection` commands,
   on native and WASM. Direct-message checks moved from `unwrap_or(false)` to
   `unwrap_or(true)`.
7. **Block alias resolution.** `is_blocked_resolved` -> `resolved_identifiers`
   expands a libp2p PeerId to its public-key hex and derived identity id, plus
   the `pk:`/`id:` prefixed legacy forms, so a UI-flavored block row is enforced
   at the transport layer.
8. **Reflected-address fix is complete for disclosure.** `15dbcde0` drops
   `swarm.external_addresses()` from the local-subnet evidence. Of the six
   remaining `external_addresses()` uses in `swarm.rs`, only `:5925` still
   chains them, and it feeds `build_seed_dial_candidates` self-exclusion, not a
   disclosure predicate.
9. **Circuit addresses remain disclosable.** The new `P2pCircuit` rejection in
   the RFC1918 predicate read as a possible relay-reachability regression. It is
   not: `is_disclosable_multiaddr` accepts a circuit marker preceded by a valid
   IP transport hop, and `exchange_response_entries_for_request` tries that
   predicate first. Relayed peers stay advertisable.
10. **No production `core_handle: None` path.** `peer_is_blocked` fails closed
    when the core handle is absent, which would silently disable every mesh
    protocol. Every call site passes `Some(Arc::downgrade(&core))`: CLI
    (`cli/src/main.rs:1778, 2931, 3358`), mobile bridge
    (`core/src/mobile_bridge.rs:753`), WASM (`wasm/src/lib.rs:1820`), and the
    integration tests. The doc comment on `default_routing_engine_handle`
    claiming CLI/WASM have no IronCore instance is stale and misleading, but no
    code follows it.

## Observations (non-blocking)

**O1 -- a storage error is indistinguishable from a block.** `peer_is_blocked`
maps `Err` to `true` and logs at `warn`. A transient sled read failure makes the
node refuse ledger exchange, reflection, registration, and relay/custody for
that peer, with no signal separating it from a real block. Fail-closed is the
right default; the observability is not. Log the `Err` arm at `error` with the
store error so Run 1 can tell them apart.

**O2 -- blocked peers bypass the inbound ledger-exchange limiter.** The
`peer_is_blocked` check sits above the token bucket, so a blocked peer's
requests never consume a token and each costs a `send_response`. Low severity --
empty response, peer must already be authenticated -- and still a large
improvement over the prior path, which processed `request.peers` first. Noted
because the surrounding comment asserts the limiter runs "BEFORE ANY WORK",
which is now true only for unblocked peers.

**O3 -- wildcard-listener concern resolved empirically.** Private disclosure
depends on `swarm.listeners()` reporting concrete per-interface addresses. The
AWS node reports `172.31.19.216`, `172.17.0.1` and loopback/link-local forms,
with no `0.0.0.0` entry, so libp2p does expand the wildcard bind on Linux.
Android and iOS still need the same confirmation during Run 1; `/api/listeners`
provides it directly.

**O4 -- UPnP removal changes desktop NAT behaviour.** `behaviour.rs` drops the
`upnp` field and `swarm.rs` drops the event arm, resolving the P0 panic by
removal. Desktop nodes lose automatic external-address mapping; inbound
reachability now rests entirely on AutoNAT, DCUtR, and relay. Run 1 should not
expect direct inbound connectivity to a NATed desktop node.

**O5 -- reflected addresses still enter seed self-exclusion.** At `:5925` a
peer-supplied reflected address can join the self-exclusion list, so a forged
observation matching a real seed address could suppress dialing that seed.
Pre-existing, low severity, not introduced by this delta. Backlog item.

**O6 -- alias resolution only covers inline PeerIds.**
`public_key_hex_from_peer_id` can only recover a key from an
identity-multihash PeerId, i.e. Ed25519. That is the only key type this project
issues, so it is correct today; it would fail open for a hashed-multihash PeerId
if another key type is ever introduced.
