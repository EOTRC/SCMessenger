## Why ancestry cannot be used

`main` is squash-merged, which creates a new commit and breaks ancestry.
`git merge-base --is-ancestor` therefore reports genuinely-merged work as
"not on main" -- the exact misreading that made PRs #118/#119 look
outstanding for a week when their content had already shipped.

`unique_patches` is `git log --cherry-pick --right-only --no-merges`,
which excludes commits whose PATCH is already applied on main regardless
of SHA. That is the only trustworthy signal here.

## Rules

| Disposition | Condition |
|---|---|
| KEEP | canonical branch, active lane, or bot-managed |
| DELETE | zero unique patches AND no open PR |
| CHERRY-PICK | has unique patches, but merging would REMOVE >500 lines from main |
| ARCHIVE | net-additive and large -- preserve as a tag, do not merge |
| REVIEW | rules cannot decide; a human reads it |

A branch is NEVER classified DELETE for being old. Age is not a rule.
REVIEW is the default, so an unclear branch is examined rather than dropped.
